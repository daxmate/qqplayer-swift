# 同步 SLO 与失败分类（T1 · 2026-11-12）

> 本文回答三件事：**什么算验收通过**、**什么算缺陷**、**失败时用户必须看到什么**。
> 口径由 2026-11-12 用户拍板（T1 任务包 §D）；实现落在
> `SyncDataSyncCoordinator` / `SyncPullRetryPolicy` / `SyncDiag`（`kind=frame` 观测行）。

## 1. 验收硬门禁（仅测试条件）

测试环境固定：

- 机器：xmini（Mac）+ iPhone 16 Pro
- 网络：**同一 5GHz WiFi**（不用 AWDL、不跨网段、不挂 VPN）
- 状态：两台设备均已解锁并前台/后台常驻（iOS 端不锁屏）

门禁（全部满足才算验收通过）：

1. 连接成功后必须完成一次同步（`phase == .finished` + `failureMessage == nil`）；
2. **0 用户可见失败**（面板不得出现错误红字 / 不得停在等待态）；
3. 吞吐 ≥ **85% 当下实测极限**——极限值由 probe 实测给出（T2 已落地：8 MiB 载荷、按真实
   传输窗口发送，探针即真实传输的缩小复刻，报出的 MB/s 就是用户在同网络下的实际速率）。

达不到时先按 §4 分类，再决定是缺陷还是环境问题。

## 2. 实际工况软要求（日常使用）

真实环境允许**慢**、允许**失败**，但**绝不允许静默**：

- 慢 → 面板显示等待提示；等对端准备时显示「对端正在整理曲库，X 秒后自动重试」；
- 失败 → 面板显示失败原因 + 主按钮恢复可点（= 手动重试入口），不得只剩一个转圈或一句「同步中」。

判据：用户任何时候看面板都能回答「现在在干什么 / 为什么慢 / 我该点什么」。

## 3. 导入中策略（对端 notReady）

对端曲库索引未到终态（正在导入 / 整理）时：

1. 对端回 `change_log_push` 空批 + `notReady=true` + `notReadyReason`（`importing` / `tidying`）；
2. 本端识别为「未就绪」而不是失败：提示 + **3 轮 × 5s 自动重试**（首次 + 3 次重发）；
3. 3 轮后仍 notReady → **显式失败**（`sync_data_pull_not_ready_timeout`），
   主按钮恢复可点 = 手动重试入口，**不再静默等待**；
4. 自动重试期间面板按秒展示倒计时（`sync_data_pull_peer_{preparing,importing}_countdown`）。

## 4. 失败分类：只有「协议失败」算缺陷

| 类别 | 典型现象 | 判定 | 处理 |
| --- | --- | --- | --- |
| 环境失败 | 对端忙（导入中 / 整理曲库）、网络断开、锁屏/后台被系统挂起、未配对 | **不算缺陷** | 显式提示 + 有限自动重试 + 手动入口 |
| 协议失败 | **已连上**之后：pull 应答超时（上限 3 次；3 个应答窗口 + 2s/5s 退避，默认窗口 20s → 最坏约 67s）、应答丢失、迟到应答被丢弃、批校验/应用失败 | **算缺陷** | 必须能靠日志 5 分钟内定位 |

协议失败的定位要求（5 分钟内）：

1. `grep SYNCDIAG` 看本轮 `kind=conn|frame|run` 行：
   - `addr` / `if` / `link`：走的哪条链路（`-1` / `unknown` = 拿不到，本身即缺陷）；
   - `pullSent` / `pullRecv` / `pullLate`：发了几次、收了几条、几条迟到；
   - `importing=1`：对端当时在导入曲库（环境失败，不计缺陷）。
2. `grep "SyncDataSyncCoordinator"` 看等待 / 重发 / 收尾行；
3. 结论必须能落到「哪一层丢的」：发送侧没发 / 网络没到 / 收到未接受 / 接受未落库。

判定原则（INV-36）：**收尾后到达的应答必须照常应用并记账**（`pullLate`），
只有「发出去且对方已应答，但本端始终没应用」才算协议失败。

## 5. 明确不做

- **双向并发写**：不支持（2026-11-12 用户决定）。同一时刻只有一端写；
- 传输层参数调优（chunk / 并发 / 续传）：不在本文范围；
- probe 吞吐值只作诊断（`probeMBps`），不是门禁：未测/失败写 `-1`（不编造）。
  探针口径 = 8 MiB 载荷 + 真实传输窗口（`min(对端声明 maxInFlight, 8)`），见 `QQPlayer/Sync/SyncProbe.swift`。
